# Product Brief

## Summary

Ghostwriter is a portfolio-first AI micro-app that rewrites short passages in stylized voices with a playful mood dial. The next version should deepen delight and make the craft legible without bloating the product.

The product should feel like an interactive art object with strong engineering under the hood.

## Goal

Ship a version of Ghostwriter that hiring managers, designers, and engineers remember after a quick demo.

## Target Audience

Primary:

- Recruiters
- Hiring managers
- design-forward product teams
- senior engineers evaluating product taste

Secondary:

- Friends and peers who will try and share the app
- portfolio visitors browsing several projects in a row

## Core Promise

Paste text, choose a voice, turn the mood dial, and watch the rewrite happen like a living edit.

## Product Principles

1. One clear joke, executed beautifully.
2. Magic first, explanation second.
3. The interface should feel authored, not templated.
4. Every new feature must improve first-session delight or portfolio credibility.
5. Technical sophistication should be visible, but never heavy.

## Approved Scope

### 1. Live Rewrite Animation

The output should no longer appear all at once. The app should stage the rewrite like a performance:

1. Source sentence stabilizes
2. Diff-style cuts begin appearing
3. Replacement phrases fade or type in
4. Final polished passage settles into place

This should feel intentional, not gimmicky.

### 2. Surprise Me

One-click demo path for portfolio visitors.

Behavior:

1. Choose a sample
2. Choose an author
3. Choose a mood
4. Immediately trigger a rewrite

The user should not need to think before getting value.

### 3. How It Works Drawer

A compact, elegant panel explaining:

- voice system
- mood dial logic
- rewrite engine
- storage and sharing
- abuse protection

This is not a docs page. It is a credibility layer.

### 4. Case Study Page

A short, visual write-up linked from the app. It should explain:

- the concept
- the interaction choices
- the prompt design
- the trust and abuse controls
- what would come next

## Explicit Non-Goals

- User accounts
- saved libraries
- collaborative features
- generic assistant chat
- enterprise positioning
- “work mode”
- audience simulation
- performance scoring

Those ideas are strategically valid in a startup context, but they weaken the portfolio artifact.

## Success Criteria

Qualitative success:

1. People immediately understand the concept
2. The app feels alive during the first interaction
3. The app is visually distinct from boilerplate AI demos
4. A reviewer can tell there is real engineering depth
5. The project page reads like a deliberate product decision, not a class assignment

## Experience Narrative

Ideal first session:

1. Visitor lands on `/ghostwriter`
2. They see a striking hero and a `Surprise Me` call-to-action
3. They watch the live rewrite animation
4. They tweak author or mood and rerun
5. They open `How It Works`
6. They visit the case study page

## Sharp Product Opinion

Do not add more complexity than the concept can support.

This project wins by being narrow, fast, polished, and surprising.
